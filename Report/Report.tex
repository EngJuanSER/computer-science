\chapter*{Abstract}
\addcontentsline{toc}{chapter}{Abstract}
This technical report details the design, implementation, and final results of the MacraScript project. MacraScript is a domain-specific language (DSL) created to address the lack of specialized digital tools for designing and visualizing macramé patterns. The project involved the development of a complete compiler in Python, featuring lexical, syntactic, and semantic analyzers, along with a Tkinter-based graphical user interface. The language supports two distinct pattern types, "Alpha" and "Normal," and generates dual graphical outputs for each: a top-down pixel-art preview and a detailed, step-by-step knot-flow diagram. This document covers the final language grammar, the complete architecture of the compiler, the logic behind the graphical rendering, and the results achieved, demonstrating a functional and effective solution that bridges the gap between traditional crafting and computational design.

\chapter{Introduction}

\section{Problem Context}
Macramé is a textile art form based on creating decorative patterns through organized knotting sequences. The planning of complex patterns is a meticulous process, prone to human error and lacking specialized digital tools. Artisans often rely on hand-drawn grids or generic design software, which are not optimized for the specific constraints of knot-based patterns~\cite{karner2005}.

\section{Project Objectives}
The primary goal of this project was to develop MacraScript, a DSL that allows designers to:
\begin{itemize}
    \item Define macramé patterns using a simple, declarative syntax.
    \item Specify parameters such as thread count, colors, and knot sequences.
    \item Generate accurate visualizations of the final pattern.
    \item Produce step-by-step graphical guides for executing the pattern.
\end{itemize}

\section{Motivation and Target Audience}
The development of MacraScript is driven by the need to provide a specialized tool for a community that has largely been overlooked by modern software development. The primary beneficiaries of this language are:
\begin{itemize}
    \item \textbf{Macramé Artisans and Designers:} Professionals and hobbyists who can now create, verify, and iterate on complex patterns with greater speed and accuracy. MacraScript reduces the tediousness of manual drafting and prevents costly errors in the middle of a physical project.
    \item \textbf{Educators and Learners:} The language serves as an educational tool, helping newcomers understand pattern construction through a logical, structured format. The dual visualization provides a clear link between the abstract code and the physical knotting process.
    \item \textbf{Digital Crafters:} A growing community of makers who merge traditional crafts with digital tools. MacraScript provides a platform for experimentation, sharing, and archiving patterns in a standardized, reproducible format.
\end{itemize}
By creating a bridge between computational thinking and textile art, MacraScript not only streamlines a creative process but also fosters a new way of thinking about and sharing traditional knowledge.

\chapter{Final Language Design}

\section{Overview}
MacraScript is a declarative DSL designed to be intuitive for macramé artisans. The language is structured around a central \texttt{PATTERN} block, which can be of type \texttt{ALPHA} (for grid-based designs) or \texttt{NORMAL} (for knot-based geometric patterns).

\section{Alphabet and Tokens}
The language's alphabet includes uppercase and lowercase letters, numbers, and the symbols \texttt{: , \{ \} ( ) "}. Reserved words, or keywords, are \texttt{START, END, PATTERN, ALPHA, NORMAL, THREADS, WIDTH, HEIGHT, COLORS, ROW, LEFT, RIGHT}.

The lexical analyzer uses the following regular expressions to tokenize the input code:

        \texttt{COLOR} & \texttt{"\#?[A-Fa-f0-9]\{6\}"} \\

\section{Final Grammar}
The final grammar for MacraScript is defined in a clear, readable EBNF format. Each production rule is explained to enhance comprehension.

\begin{lstlisting}[language=bash, caption={Final EBNF Grammar for MacraScript}, basicstyle=\ttfamily\small]
(* Program Structure: Defines the main container for a pattern *)
<program> ::= "START" <type> <config> <pattern> "END"

(* Pattern Type: Specifies one of the two supported pattern styles *)
<type> ::= "ALPHA" | "NORMAL"

(* Configuration Block: Contains all setup parameters *)
<config> ::= <threads> [<dims>] <colors>
<threads> ::= "THREADS" ":" <INTEGER>
<dims> ::= ("WIDTH" | "HEIGHT") ":" <INTEGER>
<colors> ::= "COLORS" ":" "(" <string_list> ")"
<string_list> ::= <STRING> ("," <STRING>)*

(* Pattern Data: The core block defining the pattern's structure *)
<pattern> ::= "PATTERN" "{" <row_list> "}"
<row_list> ::= <row>+
<row> ::= "ROW" ":" "(" <sequence> ")"

(* Sequence Types: Defines the content of a row based on pattern type *)
<sequence> ::= <alpha_sequence> | <normal_sequence>
<alpha_sequence> ::= <INTEGER> ("," <INTEGER>)* (* A list of color indices *)
<normal_sequence> ::= <DIRECTION> ("," <DIRECTION>)* (* A list of knot directions *)
<DIRECTION> ::= "LEFT" | "RIGHT"
\end{lstlisting}

\section{Syntax Examples}

\subsection{Alpha Pattern Example}
\begin{lstlisting}[language=bash, caption={Alpha pattern for a 4x4 checkerboard}]
START ALPHA
THREADS: 4
WIDTH: 4
HEIGHT: 4
COLORS: ("red", "blue")
PATTERN {
    ROW: (0, 1, 0, 1)
    ROW: (1, 0, 1, 0)
    ROW: (0, 1, 0, 1)
    ROW: (1, 0, 1, 0)
}
END
\end{lstlisting}

\subsection{Normal Pattern Example}
The syntax for Normal patterns was refined to be more intuitive. Instead of specifying individual knots, the user defines rows of knot directions. The compiler automatically handles the staggered pairing of threads.

\begin{lstlisting}[language=bash, caption={Normal pattern with alternating rows}]
START NORMAL
THREADS: 8
COLORS: ("red", "blue", "yellow", "green")
PATTERN {
    ROW: (RIGHT, RIGHT, RIGHT, RIGHT)
    ROW: (LEFT, LEFT, LEFT)
    ROW: (RIGHT, RIGHT, RIGHT, RIGHT)
}
END
\end{lstlisting}

\chapter{System Architecture and Implementation}

\section{Compiler Pipeline}
The MacraScript compiler is a Python application that processes the source code in three main phases:

\begin{enumerate}
    \item \textbf{Lexical Analysis (\texttt{lexical.py}):} This module uses regular expressions to break the input code into a list of tokens. It correctly handles keywords, identifiers, color names, and hex color codes.
    
    \item \textbf{Syntactic Analysis (\texttt{sintactic.py}):} A recursive descent parser validates the token sequence against the defined grammar. It builds a dictionary representing the abstract structure of the code, which is passed to the next phase.
    
    \item \textbf{Semantic Analysis (\texttt{semantic.py}):} This is the core of the compiler's logic. It takes the parsed structure and:
    \begin{itemize}
        \item Validates semantic rules (e.g., thread counts, color indices).
        \item For \texttt{NORMAL} patterns, it translates the abstract rows of directions into a concrete list of knot instructions, automatically calculating the correct staggered thread pairs for each knot.
        \item Produces a high-level \texttt{MacraPattern} object that is easy for the rendering engine to consume.
    \end{itemize}
\end{enumerate}

\section{Graphical User Interface (\texttt{compiler.py})}
The main application module uses Tkinter to provide a simple GUI. It includes a text editor for writing MacraScript code and two canvas widgets for displaying the graphical outputs. This module orchestrates the compilation pipeline and calls the appropriate drawing functions. A mockup of the proposed UI is shown in Figure \ref{fig:ui_mockup}.

\chapter{Results and Discussion}

\section{Graphical Outputs}
The final implementation successfully generates two distinct and coherent visualizations for each pattern type, providing both a final preview and a functional guide.

\subsection{Pixel Art Visualization}
This view shows a top-down preview of the finished piece.
\begin{itemize}
    \item \textbf{Alpha:} Renders a grid of colored squares.
    \item \textbf{Normal:} Renders a grid of colored diamonds. The color of each diamond correctly represents the color of the \textit{active} thread that forms the knot, ensuring visual consistency with the knot diagram.
\end{itemize}

\subsection{Knot-Flow Diagram}
This view provides a step-by-step guide for the artisan.
\begin{itemize}
    \item \textbf{Alpha:} Renders a snake-like flow of nodes. The connecting lines are colored to match the node they originate from, improving clarity.
    \item \textbf{Normal:} Renders a detailed lattice diagram showing the path of each thread. The knots are represented by circles, colored according to the active thread, with an arrow indicating the knot's direction.
\end{itemize}

\chapter{Design Rationale and Reflection}

\section{Language Design Choices}
The design of MacraScript was guided by the principle of simplicity and a focus on the domain's specific needs.
\begin{itemize}
    \item \textbf{Declarative Syntax:} We chose a declarative style over an imperative one to make the language more accessible to users without a programming background. Artisans think in terms of pattern structure, not algorithmic steps. The syntax \texttt{THREADS: 8} is more intuitive than a variable assignment like \texttt{let threads = 8;}.
    \item \textbf{External DSL:} An external DSL with its own compiler provides maximum flexibility. It allowed us to define a clean syntax, create a robust error-handling pipeline, and generate highly specialized graphical outputs, which would be difficult to achieve with an internal DSL hosted in a general-purpose language.
    \item \textbf{Abstraction in Normal Patterns:} The most significant design decision was to abstract the knot-pairing logic in \texttt{NORMAL} patterns. Manually tracking which threads form a knot in staggered rows is a major source of errors. By having the user only specify the knot's direction (\texttt{LEFT} or \texttt{RIGHT}), we hide this complexity. The compiler handles the logic of pairing threads (1-2, 3-4 in one row; 2-3, 4-5 in the next), dramatically improving usability.
\end{itemize}

\section{Compiler and Visualization Choices}
\begin{itemize}
    \item \textbf{Dual Graphical Output:} Providing two visualizations was crucial. The \textbf{Pixel Art View} gives an immediate, high-level preview of the final aesthetic, which is essential for design iteration. The \textbf{Knot-Flow Diagram} is a functional, step-by-step guide that is indispensable for the actual crafting process. This duality directly serves the two key phases of a macramé project: design and execution.
    \item \textbf{Python and Tkinter:} Python was chosen for its rapid development capabilities and extensive libraries. Tkinter, while not the most modern UI toolkit, is included in the standard library, ensuring that the compiler is easy to run on any system without complex dependencies. This aligns with the goal of making the tool accessible.
\end{itemize}

\section{Lexical Errors}
These occur when the input contains characters not recognized by the language's alphabet.
\begin{itemize}
    \item \textbf{Example:} Using an invalid character like \texttt{@} or \texttt{\$}.
    \item \textbf{Detection:} The lexer's \texttt{MISMATCH} rule catches any character that does not match a defined token.
    \item \textbf{User Feedback:} \texttt{Lexical Error: Unexpected character '@' at line 5, column 10.}
\end{itemize}

\section{Syntactic Errors}
These occur when the code violates the language's grammar rules, even if the tokens are valid.
\begin{itemize}
    \item \textbf{Examples:}
    \begin{itemize}
        \item Missing a keyword (e.g., forgetting \texttt{START}).
        \item Forgetting a colon, parenthesis, or brace (e.g., \texttt{THREADS 8}).
        \item Incorrect order of statements (e.g., placing \texttt{COLORS} before \texttt{THREADS}).
    \end{itemize}
    \item \textbf{Detection:} The recursive descent parser in \texttt{sintactic.py} expects specific tokens at each step. If the current token does not match, it raises a \texttt{SyntaxError}.
    \item \textbf{User Feedback:} \texttt{Syntax Error: Expected ':' after THREADS, found '8' at line 2.}
\end{itemize}

\section{Semantic Errors}
These occur when the code is syntactically correct but logically inconsistent with the language's rules.
\begin{itemize}
    \item \textbf{Examples:}
    \begin{itemize}
        \item \textbf{Inconsistent Dimensions:} Defining \texttt{HEIGHT: 5} but providing only 4 rows in an \texttt{ALPHA} pattern.
        \item \textbf{Index Out of Bounds:} Using a color index of \texttt{3} when only 2 colors have been defined.
        \item \textbf{Invalid Value:} Specifying \texttt{THREADS: 0}.
        \item \textbf{Incorrect Knot Count:} Providing 3 knot directions in a \texttt{NORMAL} row that expects 4.
    \end{itemize}
    \item \textbf{Detection:} The \texttt{semantic.py} analyzer performs checks after the code is parsed, validating the relationships between different parts of the program.
    \item \textbf{User Feedback:} \texttt{Semantic Error: Row 3 has 5 colors, but pattern width is 4.}
\end{itemize}
